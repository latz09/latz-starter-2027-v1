Latz Starter: Start Here

The whole per-client flow, in order. The README is the full reference; this page is the checklist you work down.

Checkboxes save in this browser, per file location.

Before you start

  • Figma screenshots exported, one per section, no comment pins or annotation UI. This is the only required input.
  • Style guide done (colors, fonts, buttons, spacing), ready to drop in docs/style-guide/.
  • Client name and live domain, if you have them.
  • Optional background: overview, wireframe, content draft, design brief. If any of these disagree with Figma, Figma wins.
  • Machine check: Node 22.12 or newer (node -v), latest starter pulled (git checkout main then git pull), logged in to Sanity.
Two rules that never change Claude never pushes or deploys, and you run npm run dev in your own terminal. Claude edits files, runs build and lint, and stops.

The flow

1. Create the client project You

Run this from the starter folder (not a client folder). It copies the starter, installs, creates the Sanity org and project, writes .env.local, and makes the first commit. It never pushes.

npm run new-client -- --name "Client Name" --domain clientdomain.com

Then open the new folder (it lands next to the starter) in VS Code with Claude Code. Add the starter folder only when you need /promote.

2. Drop the source material in docs/ You

  • Figma screenshots go straight in docs/. Name them NN-<page-slug>-page-<section>.png, for example 01-home-page-landing-hero.png. The number keeps top-to-bottom order.
  • Style guide goes in docs/style-guide/.
  • Optional: overview, wireframe, content draft, design brief in docs/.
npm run docs

That shows exactly what /schema and /section will read. Fix anything it flags before moving on.

3. Build the design system Claude You review

In Claude Code run /theme. It reads the style guide, writes docs/style-guide/tokens.json, and pauses for your review. Approve it and it runs the theme script (Tailwind config, globals.css, fonts, theme config).

Then start npm run dev in your terminal and open /design to check buttons, colors and typography.

Manual version without Claude:

npm run theme
npm run theme -- --init

(--init writes a blank tokens.json to fill in by hand.)

4. Schemas, queries and page files Claude You approve

Run /schema. It shows an analysis first (including where optional docs disagree with Figma) and asks behavior questions. Then it builds in three phases. Approve each phase before it moves on. At the end of Phase 1 it writes the page copy to docs/seed/.

Need a page or section by hand:

npm run new-page -- <slug>
npm run new-section -- <page> <section>
npm run remove-page -- <slug>

5. Seed the copy into Sanity You

Only after /schema Phase 3. Always in this order. Seeding is fill-empty only and never overwrites Studio edits.

npm run seed -- --dry-run --offline

Checks the seed files themselves, no network.

npm run seed -- --dry-run

Shows what would be written to Sanity, and names any drafts it would fill.

npm run seed

The real write. Then open /latz-studio and confirm the content is there.

Never --force on a site with real edits --force overwrites. On a live client, run a dry run first, every time. Images are skipped for now: upload them in the Studio.

6. Build each section Claude You review on localhost

One section at a time, from its screenshot, against the page's real query:

/section home landing-hero

It ends with what to check on localhost. Review, then do the next one. Claude runs build and lint after each.

7. Per-client settings You

  • sanity/branding.js: Studio title, logo, CMS guide URL.
  • public/cms-guide.html: replace the placeholder with the client's editing guide. Keep its noindex meta tag.
  • data/config/contact.js: form fields, colors, email copy.
  • data/config/redirects.mjs: old URLs, for rebuilds.
  • .env.local: add RESEND_API_KEY and CLIENT_EMAIL.
  • Studio, SEO Settings: fill in everything, including Site URL (must match NEXT_PUBLIC_SITE_URL) and Email Logo.
  • Test the Presentation tool (live preview and click to edit).
  • Test the contact form end to end.

8. Pre-launch check You

npm run check
npm run build
npm run lint

Fix everything they report. Remove /design and its checklist at launch.

9. Off-machine items Browser You

These can't be done from the repo:

  • GitHub: create the client repo, git remote add origin <url>, git push -u origin main.
  • Vercel: import the repo. Copy every value from .env.local into Vercel env vars (Production and Preview), then redeploy. NEXT_PUBLIC_* values are baked in at build time.
  • Vercel Node version: an open engines range builds on the newest Node. To match local Node 22, set "22.x" in that client's package.json.
  • Sanity CORS for the live domain, with Allow credentials (skip if you passed --domain in step 1):
npx sanity cors add https://clientdomain.com --credentials
npx sanity cors add https://www.clientdomain.com --credentials
  • No wildcard like https://*.vercel.app. Add an exact preview URL only if needed, and remove it afterwards.
  • Invite the client: sanity.io/manage, their organization, project, Members, Invite as Editor.
  • At handover: transfer the Sanity organization's billing and ownership to the client.

If something breaks

  • Lots of "tarball corrupted" or TAR_ENTRY_ERROR during install: bad npm cache. Run npm cache clean --force, delete node_modules, run npm ci.
  • Live preview only updates on publish: check components/ui/VisualEditingClient.js (the debounced refresh handler).
  • Studio won't load on the live domain: the domain is missing from Sanity CORS, or Allow credentials is off.
  • A .text-* class does nothing: it isn't defined in app/globals.css. Font sizes only come from there.
  • Anything else: the README has the full reference.
